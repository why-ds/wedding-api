# 관리자 기능과 보안 점검

점검일: 2026-09-14. 로컬 개발 초안이며 운영 배포 완료를 의미하지 않습니다.

EC2 미리보기 구성과 실행 순서는 [배포 안내](../deploy/README.md)에 별도로 정리했습니다. `postgres,preview`는 영구 저장과 가상 공개 카탈로그를 함께 사용하는 프로필입니다. CI에 PostgreSQL 16 통합 테스트 3개를 추가했으며, 실제 통과 여부는 Actions 결과로 구분합니다.

## 실행과 관리자 로그인

- React: http://127.0.0.1:5173/
- 관리자: http://127.0.0.1:5173/admin
- Spring 상태: http://127.0.0.1:8080/actuator/health
- 기본 `demo` 프로필은 DB 없이 실행하며 계정·찜·업체 초안·이력을 메모리에 저장합니다. 서버 재시작 시 초기화됩니다.
- demo 관리자 이메일 기본값은 `admin@yeon.local`입니다. 임의 생성한 비밀번호는 서버 작업 디렉터리의 `.runtime/admin-initial-login.txt`에서 확인합니다. 이 파일은 Git 제외 대상이며 공유하지 않습니다. 재시작 후에는 파일을 다시 확인하세요.
- 가입 화면으로 관리자 권한을 얻을 수 없습니다. 기존 일반 회원 이메일과 bootstrap 이메일이 같으면 자동 승격하지 않고 시작을 중단합니다.
- PostgreSQL 모드는 bootstrap이 기본 비활성입니다. 최초 발급 시에만 `WEDDING_ADMIN_BOOTSTRAP_ENABLED=true`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`를 환경에 공급합니다. 발급 후 bootstrap을 끄고 비밀번호 환경 변수를 제거합니다. 관리자 생성과 권한 등록은 하나의 DB 트랜잭션입니다. 기존 관리자 비밀번호를 bootstrap으로 바꾸지는 않습니다.

## 구현 범위와 데이터 구조

예식장·스튜디오·드레스·메이크업·예물·한복·예복의 기관명, 지점명, 카테고리, 지역, 주소, 공개 연락처, 출처 URL을 등록합니다. 개별 등록·수정·보관, CSV 검증·일괄 저장, 상태별 목록, 최근 변경 이력을 지원합니다.

`operations` 서비스가 검증과 업무 흐름을 담당하고 저장은 `CatalogDraftRepository`의 demo/PostgreSQL 구현으로 나눴습니다. 기존 공개 검색과 가격 계산은 별도입니다. 초안의 기관명과 지점명은 입력 항목이며, 아직 정식 기관·지점 ID로 연결하지 않습니다.

V902 마이그레이션:

| 테이블 | 역할 |
| --- | --- |
| `iam.platform_role` | 플랫폼 권한 종류 |
| `iam.user_platform_role` | 회원의 플랫폼 권한 |
| `ops.catalog_draft` | 형식이 제한된 초안 JSON, 고유 코드·업체 식별 해시, 상태, 버전 |
| `ops.catalog_import` | 업로더 소유 미리보기, 만료 시간, 저장 결과 |
| 기존 `ops.audit_event` | 관리자·작업·대상·시각 기록 |

기관·지점·상품·가격표의 정규화된 기존 설계는 유지합니다. 향후 공개 승인 시 초안을 해당 테이블로 변환하고 검수자, 출처 확인 시각, 가격 유효 기간을 검증해야 합니다. 현재는 초안을 저장해도 사용자 검색에 나타나지 않습니다.

## 업무 규칙

1. 개별 등록과 CSV 모두 같은 필드 검증을 적용합니다. 관리 코드 또는 업체명·지점명·카테고리·주소 조합의 중복은 거부합니다. 보관된 초안의 코드도 재사용하지 않습니다.
2. CSV는 UTF-8(BOM 허용), 256KiB 이하, 최대 100개 데이터 행, 지정된 8개 헤더만 허용합니다. 따옴표로 감싼 쉼표는 처리합니다. 파일명을 저장 경로로 사용하지 않습니다.
3. 모든 행이 유효할 때만 업로더에 묶인 30분짜리 미리보기 ID를 발급합니다. 다른 관리자는 해당 ID로 저장할 수 없습니다.
4. 저장 시 서버에 보관한 행만 사용합니다. 미리보기 후 발생한 중복도 다시 차단하며, 일괄 저장은 전부 성공하거나 전부 취소됩니다.
5. 같은 미리보기 ID로 재요청하면 기존 결과를 반환합니다. 새 미리보기로 같은 업체를 다시 등록하면 중복 오류입니다. demo에서는 만료 자료 정리 후 ID가 사라질 수 있고, PostgreSQL은 완료 결과를 보관합니다.
6. 수정·보관은 클라이언트가 읽었던 버전이 현재 버전과 같아야 합니다. 충돌은 409로 반환합니다. 보관은 삭제가 아니며 이후 수정은 차단합니다.
7. 변경과 감사 기록은 같은 DB 트랜잭션에서 처리합니다. 감사 기록에는 원문 연락처·비밀번호를 넣지 않습니다. 변경 전후 값 전체를 복원하는 기능은 없습니다.

## API

모든 경로의 공통 접두사는 `/api/v1/admin`입니다. 서버의 현재 관리자 권한이 필요하며 쓰기 요청은 세션 CSRF 토큰이 필요합니다.

| 메서드·경로 | 동작 |
| --- | --- |
| GET `/catalog?page=0&status=DRAFT` | 20건 단위 목록, 상태 필터 생략 가능 |
| POST `/catalog` | 업체 초안 생성 |
| PUT `/catalog/{id}` | `{data, version}`으로 수정 |
| POST `/catalog/{id}/archive` | `{version}`으로 보관 |
| GET `/imports/template` | CSV 양식 다운로드 |
| POST `/imports/preview` | multipart `file` 검증 |
| POST `/imports/{id}/commit` | 검증된 미리보기 저장 |
| GET `/audit` | 최근 변경 50건 |

CSV 열: `externalKey,organizationName,branchName,category,region,address,publicPhone,sourceUrl`.

## 적용한 보안·오류 대응

- API 경로와 서비스에서 관리자 권한을 검사합니다. 세션에 임의의 `ROLE_ADMIN`을 넣어도 실제 권한 기록이 없으면 거부합니다.
- 가입 JSON의 `admin`, `role` 등 알 수 없는 필드를 거부합니다. 관리자 발급은 내부 초기화 코드로 제한합니다.
- BCrypt 비용 12, 비밀번호 UTF-8 72바이트 상한, 세션 갱신, HTTPOnly/SameSite 쿠키, CSRF 검증과 기존 로그인 시도 제한을 유지합니다.
- JSON 본문 256KiB 제한은 Content-Length가 없는 요청에도 적용합니다. multipart는 파일 256KB, 요청 512KB로 제한합니다.
- CSV 내용·필수 값·길이·중복·카테고리를 검증합니다. 이름·주소의 수식 시작 문자와 제어 문자를 거부하며, URL은 인증정보 없는 http(s) 형식만 허용합니다. URL 자동 요청은 하지 않습니다.
- DB 쿼리는 바인딩 파라미터를 사용합니다. 유일성 제약과 버전 조건으로 동시 변경을 방어합니다.
- 입력 오류는 거부된 원문 값을 응답에 포함하지 않습니다. 예기치 않은 오류는 참조 ID를 주고 내부 오류 메시지를 노출하지 않습니다.
- React 데이터 요청과 CSRF 요청에 20초 제한을 적용했습니다. 보관 실패도 열린 대화상자 안에서 확인할 수 있습니다.

## 검증 증거와 한계

- 기존 가격 계산 5개, 회원 통합 6개, 컨텍스트 1개, 관리자 통합 8개 테스트가 통과했습니다.
- 관리자 테스트는 무권한 접근·권한 위조, CSRF, 입력 크기·CSV 형식, 업로드 소유권, 재요청, 저장 전 중복 충돌, 버전 충돌과 감사 기록을 포함합니다.
- React 타입 검사·운영 빌드 통과. npm audit는 실행 당시 알려진 취약점 0건이었습니다. Java 의존성 전체 CVE 감사나 침투 테스트를 수행한 결과는 아닙니다.
- Vite → 실제 Spring 연결에서 관리자 로그인, 개별 생성·수정·보관, multipart CSRF, CSV 미리보기·저장·동일 요청 재실행, 감사 이력, 공개 검색 응답을 확인했습니다. 검증용 가상 초안은 보관 처리했습니다.
- 테스트는 demo 저장소 기반입니다. 실제 PostgreSQL 마이그레이션·JDBC 실행·DB 동시성 검증과 브라우저 상호작용 자동화는 아직 수행하지 않았습니다.

## 다음 개발 우선순위

1. PostgreSQL 실환경 통합 테스트: V1~V902 적용, 관리자 발급 실패 롤백, 동시에 발생한 CSV 중복 및 같은 ID 재요청, 재시작 후 데이터 유지.
2. 초안 검수·공개 전환: 기관/지점 정식 ID, 제공 서비스, 가격표·옵션·유효 기간·출처, 승인 권한 및 게시 이력. 금액을 모르면 무료나 확정 가격으로 표시하지 않습니다.
3. 관리자 계정 운영: 이메일 인증, 비밀번호 재설정·변경, MFA, 권한 부여·회수 이력과 관리 화면. 현재 관리자와 일반 회원은 같은 로그인 정책입니다.
4. 운영 인프라: HTTPS와 Secure 쿠키 강제, 공유 세션·분산 시도 제한, DB 최소 권한, 비밀 관리·백업 복원·개인정보 보존 정책, 업로드/감사 기록 보존 기한과 정리 작업.

현재 `postgres` 프로필에도 가상 가격 fixture가 포함됩니다. 운영 프로필·실제 가격 데이터·예약·결제·범용 견적 엔진이 구현되기 전에는 운영 서비스로 취급하지 않습니다.
